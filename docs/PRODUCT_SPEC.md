# MindOS Radar 产品说明（v0.1）

更新日期：2026-11-19

## 1. 产品定位

MindOS Radar 是面向个人研究与技术信息跟踪的本地工具。它把经过筛选的公开来源和用户本地导入内容汇集到独立 SQLite 数据库，通过搜索、主题规则、质量统计、规则分析和可选 AI 辅助，帮助用户整理信息并保留采集与分析记录。

当前版本为单用户、本机运行的开发版本。它不提供账号体系、团队协作或公网托管能力。

## 2. 目标用户与主要任务

- 个人研究者：订阅已验证来源、按需采集、搜索和筛选条目。
- 信息整理者：建立包含词/排除词/来源过滤的主题，标记已读、收藏和备注。
- 课程或功能评估者：使用虚构样本离线复现导入、规则分析、统计和导出流程。
- 需要 AI 辅助的用户：在查看输入范围和费用估算后，手动创建并执行分析任务。

## 3. 产品边界

### 本版本包含

- 来源注册表、分级核验和订阅管理。
- RSS/Atom、声明式 JSON 与专用适配器采集；本地 CSV/JSON/JSONL 导入。
- 条目去重、搜索、阅读状态、收藏、备注、主题匹配和采集运行历史。
- 本地统计、规则分析、CSV/JSON/Markdown 导出及离线课程案例。
- 可选 DeepSeek 任务流：预览、预算检查、任务状态管理、结构化结果校验和用量估算记录。
- 本机服务端渲染 Web 界面及 JSON API。

### 本版本不包含

- 多用户、身份认证、远程访问或公网部署。
- 未经核验的来源自动采集；95 个候选源仍须逐条验证。
- 自动后台 AI 批处理或无确认的付费 API 调用。
- 绕过登录、付费墙、验证码、robots 或反爬措施。
- 法律许可结论、内容再分发权或已确定的开源许可证。
- 真实 DeepSeek 端到端验收；当前没有真实 API 调用证据。

## 4. 核心使用流程

1. 初始化独立运行数据库，并校验/同步来源注册表。
2. 浏览来源，启用已标记为 `integrated` 的来源订阅。
3. 手动或按需执行采集；查看运行结果和错误状态。
4. 在信息流中检索、筛选、阅读、收藏、备注，或建立主题规则。
5. 运行本地规则分析和统计，按需导出结果。
6. 如需 AI，先预览所选条目、输入摘要和估算费用；再显式创建并执行任务。

## 5. 功能和验收边界

| 能力 | 当前行为 | 完成边界 |
|---|---|---|
| 来源目录 | 108 条来源条目；状态以注册表为准 | 13 条 integrated、95 条 candidate；不可按目录存在推断其均可用 |
| 采集 | 仅允许已集成来源进入订阅采集 | 连通性和两轮幂等证据以 `docs/evidence/` 中实际记录为准 |
| 本地整理 | 搜索、筛选、状态、主题和规则分析 | 不代表 AI 语义分析或来源内容完整 |
| 导出 | CSV、JSON、Markdown | 导出可能包含来源元数据、备注等本地数据，应由用户保管 |
| AI | 可配置 DeepSeek；假 provider 仅用于测试/演示 | 真实调用为 NOT_RUN；假结果不能用于真实决策 |
| 旧通知桥接 | 只读查询旧数据库 | 不迁移、不写入旧库，不改变旧项目 |
| 发布 | 公开可见代码快照 | LICENSE/权属未定；公开可见不等于授予复制、修改或分发许可 |

## 6. 数据与隐私原则

- 正式运行数据、设置、秘密和数据库放在 `data/`，该目录被 Git 忽略。
- API Key 通过环境变量或本地 `data/secrets.json` 提供；界面和 API 仅显示配置状态。
- 旧通知库仅允许只读连接；新项目拥有独立数据库。
- 来源默认关闭。内容权利未确认时采取保守处理；不将第三方条款或候选目录标签当作法律结论。
- AI 仅由用户显式触发；输入先做 PII 基础脱敏，默认发送标题/摘要，正文纳入条件受 rights 状态约束。
- 导出、备份和本地运行数据不得因其位于项目目录就视为可提交或可外发。
